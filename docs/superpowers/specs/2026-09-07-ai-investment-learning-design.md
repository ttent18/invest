# AI投資支援システム 設計書

作成日: 2026-09-07 / 最終更新: 2026-09-07

**利用者は投資初心者である。用語は付録Aを参照。設計・実装・通知文面のいずれでも投資用語を説明なしに使わないこと。**

## 1. 背景と目的

SBI証券口座を持つ投資初心者が、AIと共に学びながら投資を行うためのシステム。

**目的は利益を得ること。** そのための手段として、判断とその根拠を記録し、
ベンチマークと比較し、振り返る。何が効いて何が効かないかを測定しなければ
「儲かる可能性が高い方」を選ぶこと自体ができないため、測定機構を中核に置く。

### 明確にしておくこと

本システムは利益を保証しない。参考にした動画の発信者自身も
「100%利益が出るわけではない」「基本的には長期のインデックス投資のほうが
パフォーマンスが良いというデータが出ている」と述べており、発信者自身は
インデックス投資家である。ベンチマーク比較を必須とするのはこのためであり、
**自分の手法がインデックスに勝てていないと判明した場合、それは有効な発見**
として扱う。

### 非目標

- 完全自動売買（発注は常に手動）
- デイトレード
- 他人が使えるプロダクトにすること

## 2. 前提と制約（調査で確定した事実）

| 項目 | 事実 |
|---|---|
| SBI証券の株式API | 個人向けの現物株API発注は提供なし。公式APIは先物・オプションのみ |
| HYPER SBI 2のローカルAPI | 「localhost:18080で使える」とする記事が多数あるが公式の裏付けなし。**信用しない** |
| SBI証券のディープリンク | 個別銘柄ページ・注文画面への直リンクは作れない（セッション依存URL、URLスキーム非公開） |
| **SBI証券の逆指値注文** | **国内株式・米国株ともに対応** |
| **SBI証券のOCO注文** | **米国株で対応。利確の指値と損切りの逆指値を同時発注できる** |
| SBI証券の約定履歴CSV | 「照会/履歴 > 約定履歴」からCSVダウンロード可能 |
| yfinanceのデータ遅延 | 日本株・米国株とも15〜20分遅延 |
| Finnhub無料枠 | 米国株リアルタイム、WebSocket対応、ティッカー数に制限 |
| Alpaca無料枠 | リアルタイムだが**IEX取引所のみ**。NYSE/Nasdaqを含まず最良気配とズレる |
| 米国市場の時間 | 夏時間 22:30〜翌5:00 / 冬時間 23:30〜翌6:00（日本時間） |
| Discordのボタン | Webhookでは不可。**Bot**（discord.py v2）が必要 |
| LINE Notify | 2025-03-31終了。Messaging APIの無料枠は月200通のみ（不採用） |

## 3. 中核となる設計判断

### 3.1 監視は自作せず、SBIの逆指値・OCO注文に委譲する

当初は15分ごとのポーリング監視を設計していたが、以下の理由で**廃止**した。

- yfinanceは20分遅延であり、遅延データで損切りを検知しても執行が間に合わない
- 手動発注が挟まるため、条件到達から約定まで数十分かかる
- ユーザーは夜間ベッドにおり、通知に反応して起きる運用を望まない

**買い注文と同時に、利確の指値と損切りの逆指値をSBIに入れる。**
以降はSBI側が24時間監視し、条件到達時に自動執行する。

これにより以下が同時に解決する。

- 撤退条件が「記録しただけの飾り」にならず、実際に執行される
- 自作の監視スクリプトが不要になる
- リアルタイムデータの必要性が下がる
- ユーザーは寝ていられる

### 3.2 分析はユーザーのトリガーで起動する

常時稼働の自動分析は行わない。**ユーザーがDiscordでコマンドを打った時だけ**
分析が走る。想定タイミングは各市場の開場前後。

- トークン消費が1日1〜2回に収まる
- 開場前にトリガーする限り、20分遅延は問題にならない（前日終値とニュースで判断するため）

**トレードオフ**: ザラ場中に新しい買い機会が生まれても、次にトリガーを
押すまで気づかない。売り側は3.1で担保されているため、失うのは買い機会のみ。
これは許容する。

### 3.3 決定的な処理とAI判断を分離する

株価取得・DB更新・通知送信は決定的なPythonツールが行う。AIにやらせると
日によって挙動が変わり、記録の信頼性が失われる。**判断がぶれるのは許容するが、
記録がぶれるのは許容しない。**

## 4. フェーズ設計

### Phase 1: 仮想資金

- 仮想資金でシミュレーション。実際の発注は行わない
- Discord通知と記録フローは最初から実装する（運用体験を金銭リスクなしに検証するため）
- CSVによる突合は登場しない（発注がないため）
- 最低20営業日運用する

### Phase 2: 実弾 + 手動発注

移行条件（第11章）を満たしてから移行する。変更点は2箇所のみ。

1. 提案にSBIで実際に打つ注文内容（買い・利確・損切り）が載る
2. ユーザーが手動発注し、Discordのボタンで約定を記録する

## 5. 全体構成

```
【日中・日本株】対話型
  ユーザーが Mac で Claude Code を開き /daily を実行
  → 対話しながら分析。学習の主戦場

【トリガー時】Discord経由
  ユーザーが Discord で /analyze jp または /analyze us を実行（スマホから）
  → Bot が分析パイプラインを起動
     ├─ market.py    株価・為替を取得
     ├─ portfolio.py 現在の保有と予算消化率を読む
     ├─ Web検索      ニュース・決算・市況を確認（知識カットオフ対策）
     ├─ Claude API   売買判断（買い/売り/何もしない）
     ├─ sizing.py    予算とリスク許容から数量を逆算
     └─ notify.py    提案があれば Discord に通知（なければ「動きなし」1行）
  → ユーザーが SBI アプリで発注（買い + OCO売り）
  → Discord の [約定を記録] ボタン → モーダルに数量と価格 → DB記録

【月1回・任意】
  SBIから約定履歴CSVをダウンロード → 取り込みコマンドで突合・補正
```

**常駐プロセスは Discord Bot のみ。** 自宅のWindowsで常時起動する。
Macは日中の対話型分析に使う（スリープしてよい）。

## 6. 予算管理とポジションサイジング

単なる収支記録ではなく、**予算からポジションサイズを逆算する**。

### 設定する上限

| 項目 | 役割 |
|---|---|
| 総予算 | 投資に回す上限額 |
| 1銘柄あたりの比率上限 | 一点集中を防ぐ |
| 同時保有銘柄数の上限 | 管理不能になるのを防ぐ |
| 現金比率の下限 | 買い余力を残す |
| 1取引あたりの損失許容額 | **数量の決定に使う** |

### ポジションサイジング

```
株価 $178、損切り $168 → 1株あたりの想定損失 $10
1取引の損失許容が総予算の2% (¥20,000 ≒ $135)
→ 買える数量は 13株が上限
```

損切りが近い（＝確信度が高い）銘柄ほど多く買え、遠い銘柄は少なくなる。
これが「予算の見合いでリスクを分散する」の実装である。

上限に触れる提案は、通知時点で数量が自動調整されるか、警告が出る。
**上限を超える提案は通知しない。**

## 7. データモデル

```
trades     -- 約定履歴: 日時, 銘柄, 売買, 数量, 単価, 通貨, 手数料
positions  -- 保有: 銘柄, 数量, 平均取得単価, 通貨, 利確価格, 損切り価格
cash       -- 現金残高: 通貨ごと (JPY, USD)
prices     -- 日次終値スナップショット（ベンチマークETFも同じ表）
proposals  -- 提案: 日時, 銘柄, アクション, 数量, 買値, 利確, 損切り,
           --      根拠, 確信度, 採用/見送り, journalへのパス
budget     -- 予算設定と現在の消化率
```

### 判断時の必須項目

以下を省略した提案は生成しない。

- 根拠
- 想定シナリオ
- **利確価格と損切り価格**（SBIに実際に打つ値。省略不可）
- 確信度

**損切り価格を決められない提案は出さない。**

### 為替の扱い

米国株はUSDのまま記録し、評価時にUSDJPYで円換算する。損益は必ず
株価要因と為替要因に分解する。

```
AAPL  +12,400円
  ├─ 株価要因 +15,100円 (+5.4%)
  └─ 為替要因  -2,700円 (USDJPY 149.1 → 148.3)
```

分解しないと、銘柄選定が良かったのか円安に助けられただけかが判別できない。

### ベンチマーク

同額をTOPIX連動ETFとS&P500 ETFに投じて放置した場合の成績を常に併記する。
実装はETFの終値を2本取得するだけ。比較対象がなければ自分の成績の
良し悪しを判断できない。

## 8. 通知設計（Discord）

**動くべき時以外は通知しない。** 定期サマリーは送らない。

| チャンネル | 内容 | 通知 |
|---|---|---|
| `#signals` | 売買提案・約定確認 | ON |
| `#journal` | 判断の全文・日次サマリー | OFF |

分析の結果アクション不要だった場合は、`#signals` に1行だけ返す
（「動きなし。保有5銘柄に変更なし」）。

### 提案フォーマット

SBIアプリで打ち込む順に並べる。誤発注を防ぐため、ティッカーと数量を最上部に固定する。

```
🔔 買い提案                         21:58

  ティッカー   NVDA / エヌビディア
  数量         3 株

  ── 買い ──
  指値 $179.00

  ── 同時に入れる売り注文 (OCO) ──
  利確  指値   $196.00   (+9.5%)
  損切り 逆指値 $168.00   (-6.1%)

  想定最大損失   ¥4,900 (予算の0.5%)   ✅
  投入後の投資額 ¥612,000 / ¥1,000,000 (61%)
  NVDA の比率    13.0% / 上限15%       ✅

  根拠  決算後の押し目。ガイダンス上方修正済み

  [📈 チャート] [📰 ニュース]
  [✅ 約定を記録] [⏭ 見送り]
```

日本株の場合は銘柄コード（例: 7203）と株数、円建て価格で同じ構成にする。

### 約定記録フロー

`[✅ 約定を記録]` を押すとモーダルが開く。**提案した数量と価格が
プリフィルされている**ため、実際の約定値と違う箇所だけ直して送信する。
送信後、残高と予算消化率が返信される。

スマホのDiscordアプリだけで完結し、PC操作を必要としない。

## 9. データソース

| 用途 | ソース | 備考 |
|---|---|---|
| 日本株の株価 | yfinance | 20分遅延。開場前トリガーなら問題なし |
| 米国株の株価 | yfinance または Finnhub | Finnhubはリアルタイム。まずyfinanceで開始し、必要なら切替 |
| 為替 (USDJPY) | yfinance | |
| ベンチマークETF | yfinance | TOPIX連動 / S&P500 |
| ニュース・決算 | Web検索 | 知識カットオフ対策。毎回実行する |

取得失敗時は例外を投げ、**古い価格を返さない**。失敗した日は欠測として
記録し、判断を行わない。

## 10. 安全装置

- **dry-run**: 送信せず標準出力に出すモード。開発時の既定値
- **上限超過の提案を出さない**: 予算・比率・保有数の上限に触れる提案は通知しない
- **損切り価格のない提案を出さない**
- **取得失敗時のスキップ**: 古い価格で判断させない
- **Phase 1では発注指示を出さない**: 仮想資金であることを通知に明示する

## 11. Phase 2 への移行条件

全て満たすこと。

1. **20営業日以上**運用した
2. ベンチマーク（TOPIX / S&P500）との比較が出せている
3. 提案フォーマットが実用に耐える（読んでそのままSBIに打てる状態）
4. 想定外のクラッシュ・データ欠損が直近10営業日でゼロ
5. **journalを読み返して、自分の判断の癖を1つ以上言語化できている**

## 12. テスト方針

TDDで実装する。yfinanceとDiscordはモックする。

重点箇所。

- `portfolio.py`: 買→売の損益計算、**特に通貨をまたぐケース**
- `sizing.py`: 損切り価格からの数量逆算、**上限に触れる境界値**
- `market.py`: 銘柄シンボルの正規化（`7203` → `7203.T`）
- `notify.py`: 送信せずメッセージ整形のみ検証

## 13. 作らないもの（YAGNI）

- **ザラ場の監視スクリプト**（SBIの逆指値・OCOに委譲。3.1参照）
- 定期サマリー通知
- ダッシュボード画面
- バックテスト機能
- 証券会社API連携
- 自動発注

## 14. 未解決の論点

- **ウォッチリストの初期構成**: 何銘柄を対象にするか
- **予算パラメータの具体値**: 総予算、1銘柄上限比率、同時保有数、損失許容率
- **判断ロジックの中身**: 何を根拠に売買を判断するか。参考動画の「+8%ルール
  のようなもの」は根拠が語られていないため**模倣しない**
- **手数料と税の扱い**: 仮想フェーズでシミュレートするか
- **Discord Bot のホスト**: 自宅Windows常時起動で決定済みだが、
  再起動時の自動復帰方法（タスクスケジューラ等）は実装時に決める

## 付録A: 用語集

本システムの利用者は投資初心者である。設計・実装・通知文面のいずれにおいても、
**投資用語を説明なしに使わない**こと。通知文面では可能な限り平易な言葉に
置き換える。

### 注文の種類

| 用語 | 読み | 意味 |
|---|---|---|
| 成行 | なりゆき | 値段を指定せず、今の値段で売買する注文 |
| 指値 | さしね | 値段を指定する注文。「179ドルになったら買う」 |
| **逆指値** | ぎゃくさしね | **指定した値段まで下がったら売る注文。損を止めるために使う** |
| **OCO注文** | オーシーオー | **利確の指値と損切りの逆指値を同時に出す注文。片方が成立するともう片方は自動キャンセル** |

### 売買と損益

| 用語 | 読み | 意味 |
|---|---|---|
| 利確 | りかく | 利益確定。売って儲けを確定させること |
| 損切り | そんぎり | 損失が拡大する前に売って撤退すること |
| 含み益／含み損 | ふくみえき／ふくみぞん | まだ売っていない状態の、帳簿上の利益／損失 |
| ポジション | | 現在保有している株 |
| ポジションサイジング | | 1銘柄にいくら投じるかを決めること |

### 市場と時間

| 用語 | 読み | 意味 |
|---|---|---|
| ザラ場 | ざらば | 市場が開いている時間帯 |
| 寄り付き | よりつき | 市場が開いた直後の取引 |
| 終値 | おわりね | その日最後についた値段 |

### 相場の言い回し

| 用語 | 読み | 意味 |
|---|---|---|
| 押し目 | おしめ | 上昇中の銘柄が一時的に下げた場面 |
| モメンタム | | 値動きの勢い |

### 銘柄と指数

| 用語 | 意味 |
|---|---|
| ティッカー | 米国株の銘柄記号（NVDA、AAPL など） |
| 銘柄コード | 日本株の4桁の数字（7203 = トヨタ自動車 など） |
| TOPIX | 東証全体の値動きを表す指数 |
| S&P500 | 米国の代表的な500社の値動きを表す指数 |
| ETF | 指数に連動する商品。株と同じように売買できる |
| ベンチマーク | 比較の基準。自分の成績をTOPIXやS&P500と比べる |
